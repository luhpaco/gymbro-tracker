# Design: Radix UI React 19 Peer Bump

## Technical Approach

Dependency-only bump of six `@radix-ui/*` ranges in `package.json` to React-19-peer-safe stable versions, regenerate `pnpm-lock.yaml`, and verify the transitive Radix line resolves onto the new internal line. No application code edits: shadcn/ui wrappers (`src/components/ui/*.tsx`) already use `React.forwardRef` + `React.ElementRef<typeof Primitive.X>` / `ComponentPropsWithoutRef`, which remain valid against the new line. The warning disappears because every `Slot` render site now resolves onto `react-slot@1.3.3`, which uses the ref-as-prop pattern and never reads `element.ref`.

Maps to proposal §Approach (Approach 1, recommended in exploration §Approaches). Spec confirmed no-delta (Engram obs #119): zero New/Modified Capabilities, `visual-design-system` §Presentation-Only Boundary stays satisfied.

## Architecture Decisions

### Decision: Bump all six vs. slot-only

| Option | Tradeoff | Decision |
| --- | --- | --- |
| Slot-only (`react-slot` 1.0.2→1.3.3) | Old `dialog`/`popover`/`select` keep their own `react-slot@1.0.2` via `react-primitive@1.0.3`; `DialogTrigger asChild`, `PopoverTrigger asChild`, `SelectIcon asChild` still warn | Rejected |
| All six to verified latest stable (`react-slot@1.3.3`, `react-dialog@1.1.23`, `react-label@2.1.15`, `react-popover@1.1.23`, `react-select@2.3.7`, `react-toast@1.2.23`) | Single coherent change; entire app Radix rendering moves onto new line | **Chosen** |

**Rationale**: Exploration §Approaches proved slot-only leaves three warning sites live. All six targets declare `react: ^16.8 || ^17 || ^18 || ^19` and resolve onto `react-primitive@2.1.10` / `react-slot@1.3.3` / `react-compose-refs@1.1.5`. Verified against npm registry as latest stable.

### Decision: No shadcn/ui wrapper edits

**Choice**: Leave `src/components/ui/{button,dialog,popover,select,toast,toaster,form,label,command}.tsx` untouched.
**Rationale**: All wrappers use `React.ElementRef<typeof X>` / `ComponentPropsWithoutRef<typeof X>`. Bumped Radix packages preserve those types — Slot 1.3.3 stays a `ForwardRefExoticComponent` (used in `form.tsx:104-107`). No `element.ref` read in app code. Exploration §Current State confirmed.

### Decision: cmdk-pinned old Radix subtree is dormant — keep it

**Choice**: Do not pnpm-override or replace `cmdk@1.0.0`.
**Rationale**: Used `Command`/`CommandGroup`/`CommandItem` tree (`src/components/ui/command.tsx`, consumed by `AddExerciseForm`) renders `Primitive.div` only — no `Slot`/`asChild` — so `react-slot@1.0.2` bundled under `cmdk` never emits the warning. Old line remains at `pnpm-lock.yaml` lines 4037–4040 (verified). `cmdk`'s `react: ^18` peer mismatch is pre-existing; documented as follow-up.

## Interfaces / Contracts

No public API change. Type-level compatibility contract:

- `@radix-ui/react-slot@1.3.3` keeps `ForwardRefExoticComponent` shape → `React.ElementRef<typeof Slot>` and `ComponentPropsWithoutRef<typeof Slot>` still resolve (consumed at `src/components/ui/form.tsx:104-107`).
- All bumped `@radix-ui/react-*` keep their root Primitive component refs → existing `React.ElementRef<typeof X>` typings in `button.tsx`, `dialog.tsx`, `popover.tsx`, `select.tsx`, `toast.tsx`, `label.tsx` remain valid.

## Testing Strategy

| Layer | What to Test | Approach |
| --- | --- | --- |
| Gates | Type, lint, build | `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build` (CLAUDE.md §Useful commands) |
| Lockfile audit | Transitive Radix resolution | After `pnpm install`: confirm one copy each of `react-primitive@2.1.10` and `react-slot@1.3.3` at app level; old copies (`1.0.3`/`1.0.2`) only under `cmdk@1.0.0` |
| Browser smoke | Warning absence + behavior | Manual script covering every affected experience (no test runner per `openspec/config.yaml` testing block) |

Manual smoke checklist (one scripted pass):

1. Forms: load `/login`, `/register`, `/exercises` — focus inputs, submit empty/invalid → expect no `Accessing element.ref` warning in DevTools console.
2. Dialog: open `/workouts/create` → trigger `DialogAddExercise` → close via overlay and `X` → no warning.
3. Popovers: open workout-create popover (`SummaryWorkoutForm`) and exercise-add popover (`AddExerciseForm`) → no warning.
4. Select + Icon asChild: on `/exercises`, open the muscle-group Select → no warning.
5. Button asChild: on `/exercises`, exercise-row action button — no warning.
6. Toasts: trigger success/error toast from any of `LoginForm`, `RegisterForm`, `SummaryWorkoutForm`, `CreateExerciseForm`, `UpdateExerciseForm` — no warning.
7. Command (`cmdk` subtree): exercise-add command palette — no warning (proves old subtree stays dormant).
