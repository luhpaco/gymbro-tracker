# Exploration: radix-react-19-peer-bump

Bump `@radix-ui/*` to versions with native React 19 support and remove the
`Accessing element.ref was removed in React 19` warning.

## Current State

Stack is React `19.2.8` / React DOM `19.2.8` / `@types/react` `19.2.18` (pinned via
`overrides`). All six Radix UI packages are pre-React-19 and their transitive
line is the old `1.0.x` internals:

| Package | Installed | Target (verified latest stable) |
| --- | --- | --- |
| `@radix-ui/react-slot` | `1.0.2` | `1.3.3` |
| `@radix-ui/react-dialog` | `1.0.5` | `1.1.23` |
| `@radix-ui/react-label` | `2.0.2` | `2.1.15` |
| `@radix-ui/react-popover` | `1.0.7` | `1.1.23` |
| `@radix-ui/react-select` | `2.0.0` | `2.3.7` |
| `@radix-ui/react-toast` | `1.2.1` | `1.2.23` |

All six target versions were confirmed against the npm registry as the latest
stable release and declare `react: ^16.8 || ^17 || ^18 || ^19` in `peerDependencies`.
They all resolve onto the new internal line (`react-primitive@2.1.10`,
`react-slot@1.3.3`, `react-compose-refs@1.1.5`, no `@babel/runtime`).

### Root cause of the warning

`@radix-ui/react-slot@1.0.2` (installed source read directly) implements `SlotClone`:

```js
cloneElement(children, {
  ...mergeProps(slotProps, children.props),
  ref: forwardedRef ? composeRefs(forwardedRef, children.ref) : children.ref
})
```

Reading `children.ref` is exactly the access React 19 removed → the warning.
Every old-line package renders `Slot` through `react-primitive@1.0.3`
(`const Comp = asChild ? Slot : node`), and the app also uses `Slot` directly in
`form.tsx` and `button.tsx`. New slot versions are fixed: `1.1.x` uses
`getElementRef`, `1.3.3` uses the ref-as-prop pattern (no `element.ref`).

### Verification of Notion claims

- `form.tsx` `FormControl` renders `<Slot ref={ref} ...>` (line 111) — the
  cited origin is confirmed, and it is one of several `Slot` render sites.
- The six installed versions and the three candidate dialogs, and `react-toast@1.2.1`
  already resolving onto the NEW line (`primitive 1.1.0`, `slot 1.1.0`, `primitive 2.0.0`)
  were all confirmed against `pnpm-lock.yaml` and `node_modules`.

## Affected Areas

- `package.json` — bump the six `@radix-ui/*` version ranges (dependency-only change).
- `pnpm-lock.yaml` — regenerated by `pnpm install` after the bump.

### UI components (already React-19-compatible; no edits required)

- `src/components/ui/form.tsx` — `FormControl` uses `<Slot ref={ref}>`; `React.ElementRef<typeof Slot>` type still resolves (Slot 1.3.3 keeps `ForwardRefExoticComponent`).
- `src/components/ui/button.tsx` — `asChild ? Slot : "button"` (Slot consumer).
- `src/components/ui/dialog.tsx` — wraps `@radix-ui/react-dialog`.
- `src/components/ui/popover.tsx` — wraps `@radix-ui/react-popover`.
- `src/components/ui/select.tsx` — wraps `@radix-ui/react-select` (also `SelectPrimitive.Icon asChild`).
- `src/components/ui/toast.tsx` / `use-toast.ts` / `toaster.tsx` — already on new line; bump is for currency/consistency only.
- `src/components/ui/label.tsx` — wraps `@radix-ui/react-label` (consumed by `form.tsx` `FormLabel`).

## Approaches

1. **Bump all six top-level packages to latest stable** (recommended).
   - Pros: single dependency-only change; fixes the warning at every `Slot` site;
     moves all app Radix rendering onto the React-19-native internal line;
     forward-compatible.
   - Cons: touches six lockfile entries; two `react-dialog`/`react-primitive`/`react-slot`
     copies remain because `cmdk` pins old versions (see Risks).
   - Effort: Low.

2. **Bump only `react-slot`** (minimal subset).
   - Pros: smallest diff; fixes the direct `form.tsx`/`button.tsx` `Slot` sites.
   - Cons: INSUFFICIENT — old-line `dialog`/`popover`/`select` keep their own
     `react-slot@1.0.2` via `react-primitive@1.0.3`, so `DialogTrigger asChild`,
     `PopoverTrigger asChild`, and `SelectIcon asChild` would still emit the warning.
   - Effort: Low.

## Recommendation

Approach 1: bump all six packages to `1.3.3`, `1.1.23`, `2.1.15`, `1.1.23`,
`2.3.7`, `1.2.23` respectively (keep caret ranges). This is the complete, minimal
fix and requires **no application code changes** — the shadcn/ui wrappers use
`React.forwardRef` + `ref` prop + `React.ElementRef`/`ComponentPropsWithoutRef`,
all still valid in React 19 and compatible with the new type surfaces.

## Risks

- **`cmdk@1.0.0` pins `react-dialog@1.0.5`, `react-primitive@1.0.3`, and
  `react-slot@1.0.2` exactly**, so the old line remains in the tree after the bump.
  It will NOT re-emit the warning because the used `Command`/`CommandGroup`/
  `CommandItem` tree renders `Primitive.div` without `asChild` (no `Slot` render).
  Residual old code stays bundled; `CommandDialog` is defined but unused.
- **`cmdk` declares `react: ^18` peer** — a pre-existing mismatch that already
  installs on React 19. Not introduced by this change; consider `cmdk` replacement
  as a separate follow-up.
- No test runner: regression is manual (build/type/lint gates + browser smoke test).

## Ready for Proposal

Yes — proceed to `sdd-propose`. Tell the user: the fix is a dependency-only bump of
six `@radix-ui/*` packages to their latest stable versions (all React-19 peer-safe);
no application code changes are required; manual regression should exercise the
login/register forms, the Add-Exercise dialog, the Add-Exercise/Summary popovers,
the exercise filter select, and toasts; a `cmdk`-pinned old Radix subtree remains
but is dormant and out of scope.
